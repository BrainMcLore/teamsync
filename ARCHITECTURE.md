# Архитектура и решения

## ADR 001 — нативные клиенты

Flutter / Dart; создаются только windows/android/ios runners. Никаких web runner, Electron или WebView. UI → контроллер → локальный репозиторий SQLite. Системный каталог приложения через path_provider. ARB + gen-l10n. Версии фиксируются lock-файлом и TOOLCHAIN.md после проверки.

## ADR 002 — постепенное включение общего backend

Целевая архитектура: FastAPI с /api/v1, PostgreSQL, приватное S3-совместимое хранилище, очередь PostgreSQL jobs и отдельный Python worker, WebSocket события. Один backend с модулями identity/teams/maps/strategies/utilities/training/schedule/demos/reviews/playbooks/bootcamp/integrations/notifications. Не создавать 14 микросервисов.

Текущий локальный режим не подтверждает серверные права и не показывает «Синхронизировано». Идентификаторы UUID, UTC даты, атомарные транзакции и версии готовят данные к синхронизации. Сервер обязан повторно проверять членство, версии и operation_id; отклонённые изменения сохраняются как конфликты, а не удаляются.

## ADR 003 — готовые карты

Встроенный набор девяти карт зафиксирован commit и SHA-256, содержит default/lower изображения и overview-калибровки. Копии материализуются в каталог приложения; пользовательские изображения не заменяются автоматически. Объекты тактики хранят координаты 0..1, уровень сохраняется в версии. Игровые координаты демо переводятся по pos_x/pos_y/scale; Z выбирает этаж. Совместимость геометрии старых записей с новой версией радара не предполагается без проверки.

## ADR 004 — нативный demo worker

Windows клиент запускает поставляемый `demo-worker/teamsync-demo.exe` без shell и без установки Python пользователем. Он скачивает публичный HTTPS-файл (с проверкой адресов и каждого redirect), безопасно распаковывает ZIP/RAR, анализирует DEM через Rust-backed demoparser2 и выдаёт JSON-line progress/result. OS Job Object ограничивает память процесса, число дочерних процессов и завершает extractor при закрытии worker; клиент ограничивает время и поддерживает отмену. Нет инъекций, чтения памяти игры или автоматизации ввода.

Позиции дискретизированы по 16 тиков, частота тиков измеряется по записанному game_time, когда данных достаточно. События сохраняются с исходным тиком. Между кадрами нет синтезированных координат. Дым/огонь представлены точками событий, не выдуманной геометрией. Подготовленный `.teamsync-review` передаётся на мобильное устройство отдельно от исходной демки.
