# TeamSync 0.4 — проверка исправлений

Дата: 2026-10-29, Europe/Lisbon. Предыдущий отчёт сохранён в CHECKS_0.3.md. SQLite остаётся v3; пользовательские записи и исходные файлы не заменялись. Открытая 0.3 не закрывалась принудительно.

## Результат

- **44 Flutter-теста проходят**, анализатор: **No issues found**. Новые проверки: плавное движение/углы/смерти/переносы/раунды, события/повтор entityid, benchmark реального разбора, catalog UI RU/EN на 320 и 1366 px, передача настоящего Demo URL. Widget-тест подтверждает изменение playhead за 16 мс без пересоздания painter/UI и остановку на pause.
- **31 Python-тест проходит**: API, реальные DEM/ZIP/RAR, installer плагинов, новый HLTV parser/cooldown, безопасные пути серверного ZIP, сохранение базы TS3, typed SteamCMD arguments и retry после exit 7. Одно прежнее предупреждение Starlette/HTTPX касается тестового клиента.
- Windows Release **0.4.0+4** собран с flavor v04, Inno Setup завершил упаковку. Обновлённый autonomous companion включён, Python пользователю не нужен.
- Android release-оптимизированный test APK собран, apksigner проверил **v2-подпись Android Debug**. Это тестовая подпись, не релиз магазина. iOS на Windows не компилировался.

## Лаги разбора

Проверен уже импортированный пользователем JSON: **17,701,144 байт, 12002 кадров, 24 раунда**. Только чтение, без изменения файла. Путь/имена игроков не включаются в отчёт или source ZIP.

Чтение/UTF-8/JSON/ReviewIndex перенесены в isolate, страница открывается сразу с индикатором. Catalog хранится в памяти; из playback убраны повторные filesystem reads, SQL notes queries, связывание всех smoke start/end и полная пересортировка событий. Timeline и интервалы индексируются один раз, новые запросы используют binary bounds. WeakReference-cache не удерживает навсегда все просмотренные матчи.

На 300 временных точках прежний поиск активных гранат занял **511080 мкс**, новый поиск активных гранат **вместе с последними событиями — 1642 мкс**, примерно **311×** быстрее для этой операции. Среднее: 1703.6 → 5.5 мкс. Полная загрузка и индексирование в этом запуске: 961 мс. Это CPU benchmark, **не измерение общего FPS/GPU**. Значения зависят от машины/прогрева; исходные числа: artifacts/verification/review-performance-04.json.

Ticker использует реальное elapsed-time; промежуточные перерисовки затрагивают слой игроков, static radar изолирован. Позиции визуально интерполируются между записанными снимками, исходные данные не переписываются. Смерти, смена стороны/раунда, разрывы и большие перемещения не сглаживаются. Footer сообщает, что это визуальное приближение. Заметки хранят точный tick и seek теперь использует этот tick; реальные события/HP/стороны не выдумываются.

## HLTV: фактически работающий путь

Пользователь явно заменил прежнее ограничение ТЗ. Реализован Windows catalog companion: public /results pages по 100 матчей, pagination/cache, фильтры команды/события/звёзд, детали выбранного матча, карты/игроки, data-demo-link и «Скачать и разобрать». Тир события задаёт тренер, позиции — из его разметки импортированных демок; звёзды HLTV не выдаются за официальный тир. Повторный импорт не стирает введённые позиции и тир.

Проверено **в автономном exe**, затем ещё раз из его окончательного пути в Windows Release: свежий запрос вернул **100 реальных результатов HLTV**. Логи JSONL: artifacts/verification/hltv-frozen-live-04.jsonl и hltv-release-live-04.jsonl. Через тот же transport получены реальные команды/карты/игроки и Demo-link выбранного матча. Используется curl_cffi browser-compatible HTTPS/TLS, public DNS pinning для redirects, cache и cooldown на 429. Личные cookies/аккаунты браузера, прокси и CAPTCHA-solver не используются.

**Ограничение архива:** Demo endpoint возвращает 302 к R2 CDN, но сам проверенный CDN отвечает **403**. Поэтому полная прямая загрузка этого архива не заявляется успешной. В приложении такой ответ открывает загрузку в браузере и автоматически включает приём нового завершённого DEM/RAR/ZIP из выбранной папки; папка запоминается. Сам браузерный download-to-import end-to-end здесь вручную не выполнялся. Возможны матчи без опубликованного Demo-link и изменения HTML/ограничений сайта. На Android/iOS этот Windows companion не запускается.

## Файлы серверов внутри программы

- Кнопки установки CS2 и TS3, выбор папки, общий controller на время переключения разделов, прогресс/отмена, сохранение root до начала загрузки. Автостарта серверов нет.
- **TeamSpeak 3.13.8 действительно скачан и распакован**, повторено frozen exe. SHA-256 совпал с закреплённым официальным архивом; Windows Authenticode: **Valid, TeamSpeak Systems GmbH**. Лицензия 68142 байта, корректный UTF-8; показывается в диалоге. Принятие требует явного checkbox/button пользователя. В QA лицензия от его имени не принималась и TS3 не запускался.
- **Официальный SteamCMD bootstrap действительно скачан, обновил себя**, после update-exit 7 повторный +quit завершился с **кодом 0**, Steam API loaded/unloaded. Authenticode обновлённого exe: **Valid, Valve Corp.** Обнаруженный exit 7 обрабатывается автоматически, параметры установки сохраняются; это покрыто тестом.
- CS2 устанавливается anonymous app_update **730 validate**, не старый app 740. **Полный CS2 download на десятки гигабайт не запускался**. Проверены bootstrap и управление командой/состояниями; фактическая установка полного game content и живой сервер ещё требуют приёмки.
- Папки ограничены выбранным TeamSyncServers/<kind>, ownership receipt, запрет linked paths/небезопасных ZIP; DB/ini/dat TeamSpeak сохраняются. Pending managed install блокирует запуск. Worker использует собственный Windows Job Object для своих SteamCMD-детей, отмена сохраняет файлы для продолжения. При первом CS2 install проверяется ≥100 GiB свободного места, для существующего update ≥10 GiB; UI показывает консервативные 110/11 GB.

## Прежние ограничения

Реальный PUG/MatchZy/TS3 LAN-сеанс с игроками, воспроизведение playdemo самой CS2, физические телефоны, iOS, живой OAuth и production-синхронизация ещё не приняты. Состояние процесса/локального порта не выдаётся за внешний сетевой доступ; firewall/NAT не меняются. TS3 остановка остаётся завершением собственного процесса ОС, без административного ServerQuery login. PDF drafts/annotations ещё не входят во все переносимые пакеты. Остальной исходный проект остаётся в ROADMAP.md. Перед обновлением сохраните материалы и закройте старое окно; используйте именно 0.4 для проверки исправленного viewer.
