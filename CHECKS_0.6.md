# TeamSync 0.6 — Android, аккаунты и составы

Дата: 2026-10-29. Предыдущие результаты сохранены в CHECKS_0.5.md.

## Реализовано

- Steam OpenID и Discord OAuth2 с серверной проверкой провайдера, одноразовыми PKCE-кодами, отдельными сессиями устройств, защищённым хранением токена и отзывом доступа. Провайдеры привязываются к устойчивому ID аккаунта; одинаковые имена аккаунты не объединяют.
- Android сохраняет незавершённый PKCE-вход в защищённом хранилище и восстанавливает возврат через deep link после пересоздания процесса. Профиль подключается повторно, обновляется при возврате в приложение; истёкшая сессия сбрасывается. HTTPS обязателен для внешнего API; обычный HTTP разрешён только для loopback-разработки. Debug network config отдельно от Release.
- Профиль с ID для приглашений, сменой имени, связанными провайдерами и активными устройствами. В сборки встроен публичный адрес API, ключей в клиенте нет.
- Приглашения конкретному аккаунту с подтверждением имени, принятием/отклонением адресатом, сроком и отзывом. Роли, игровые роли, основной/запасной/штаб, выход и передача владения. Удаление/понижение отправителя отзывают или ограничивают его приглашения. Все права проверяются сервером.
- Состав можно сохранить в рабочую область: ID участников устойчивы при переименовании, пространства разных серверов/аккаунтов разделены. Удалённый участник перестаёт быть исполнителем заданий. Это снимок состава: файлы и тактики между устройствами пока не синхронизируются.

## Проверено

- 51 Flutter-тест проходят; отдельный сетевой HLTV-тест пропускается по умолчанию. Анализатор: No issues found.
- 39 Python-тестов проходят. Дополнены проверки целевого приглашения, чужого адресата, срока/отзыва/понижения отправителя, ролей, удаления, профиля, отмены входа, протокольной проверки Steam и Discord issuer. Одно предупреждение Starlette/HTTPX относится к тестовому клиенту.
- Реальный Android 15 / API 35 x86_64 на Windows WHPX: integration_test/accounts_android_test.dart прошёл. Настоящие HTTP-запросы, Android Keystore, PKCE exchange и повторная загрузка токена; два разных аккаунта, приглашение, принятие, изменение роли, удаление и потеря доступа; профиль Flutter открывается без ошибок. Ответы внешнего провайдера в этом локальном сценарии заменены отдельным QA-сервером. Это не имитация обычной серверной авторизации в производственном API: fixture не поставляется с серверным архивом.
- Windows Release 0.6.0+6 и установщик собраны. Android release test APK собран и проверяется отдельно. Магазинная подпись не настроена, iOS не собирался.

## Общий сервер

Реально создан закрытый GitHub-репозиторий BrainMcLore/teamsync-api, Render Free Web Service во Frankfurt и отдельный Neon Free PostgreSQL 18 во Frankfurt. В кабинете Neon подтверждено Expires: Never. Платные тарифы не включались. После сохранения закрытых настроек опубликованный API https://teamsync-api-ui7n.onrender.com/api/v1/health вернул HTTP 200, version=0.6.0, providers.steam=true и providers.discord=true.

Создано Discord-приложение TeamSync, его redirect указывает на HTTPS callback API; Client Secret и DATABASE_URL находятся только в настройках Render. Репозиторий и архивы не содержат этих ключей. Производственный hosted запуск не допускает временную SQLite. Лог health без персональных данных: artifacts/verification/production-health-06.json.

У Render есть сон после простоя и лимиты Free; клиент повторяет безопасную проверку подключения. У выбранной базы нет 30-дневного срока. Условия сторонних сервисов могут измениться. Сведения о переносе и восстановлении: FREE_HOSTING.md.

Настоящий Discord-вход на опубликованном сервере проверен отдельно от локальной имитации. Проверка настоящего Steam-аккаунта и реального Android-телефона ещё требуется. Автоматическая проверка обоих провайдеров покрывает запросы и проверку подписанных/подтверждённых ответов, но не интерфейс их реального входа.

Живая проверка Discord на опубликованном сервере успешно завершена с участием пользователя: реальный OAuth callback → PKCE exchange → /me вернул провайдер discord, затем временная сессия отозвана через logout. Токен не записывался в файлы. Лог результата: artifacts/verification/live-oauth-06.log (в source ZIP не включается).

Дополнительная проверка настоящего cold start на Android выполнена: запрос PKCE сохранён в Android Keystore отдельным debug QA entry point; процесс завершён, установлен обычный main APK с сохранением данных, передан новый intent teamsync://auth/callback. Обычный клиент сам открыл профиль, восстановил PKCE и получил сессию. Подтверждение: android-cold-result-06.log и android-cold-login-06.png. Debug helper не является release entry point. Первоначальная попытка через flutter test не сохраняла тестовые данные при очистке пакета, поэтому приёмка выполнена с отдельным подготовительным debug APK и обычным приложением.

APK установлен на эмулятор и запущен как обычное приложение (не test entry point), холодный запуск прошёл без AndroidRuntime/Flutter ошибок. apksigner подтвердил v2 test/debug подпись. После исправления первого экрана повторно прошёл полный набор 51 Flutter-теста. Серверный архив проверен: только 14 файлов API/документации, без QA fixtures, локальных баз или секретов.
