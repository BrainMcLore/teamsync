# TeamSync — продолжение работы на Arch Linux

Подготовлено 2026-11-01. Этот файл передаёт рабочий контекст, а не полный дословный чат.

## Что требуется пользователю

Нативное приложение TeamSync для CS2, без веб-оболочки, русский и английский интерфейс. Windows и Android уже собирались; нужна возможность продолжить разработку на Arch Linux. Старый Windows-компьютер остаётся доступным. По прямому уточнению пользователя Linux — только среда разработки. Целевые платформы приложения — Windows и Android. Linux-порт не создавать.

Приоритеты: общие тактики всей онлайн-команды, вход Steam/Discord, состав из аккаунтов игроков, каталог HLTV и скачивание/разбор демок, заметки к точному таймлайну, готовые карты включая Cache, маркеры T/CT, PDF-плейбук со снимками тактик, тренировки и буткемп с установкой локальных серверов CS2/TeamSpeak. Не возвращать создание офлайн-аккаунтов.

## Текущее состояние

Клиент: Flutter, client/pubspec.yaml — 0.8.0+8. Использованный SDK Flutter 3.47.8 / Dart 3.13.7. Сервер: Python/FastAPI/SQLAlchemy/PostgreSQL. Парсер: отдельный Python worker, demoparser2; на Windows собран PyInstaller. Нативный загрузчик HLTV: C++/WebView2.

Последние исправления 0.8:
- AccountClient отправляет JSON явными UTF-8 байтами с Content-Length: раньше кириллица ломала отправку тактик через ISO-8859-1.
- Создание локальных команд из рабочего интерфейса удалено; отображаются серверные привязки. Старые материалы не удалены, могут быть привязаны к онлайн-команде.
- Каталог/карточки HLTV при блокировке HTTP используют изолированный WebView2-сеанс; человеческая проверка остаётся за пользователем. 429 соблюдается. Время ожидания каталога — 6 минут.
- Проверено на настоящем сервере: очередь тактики обработана, затем в реальном интерфейсе команды отображалось «Тактики синхронизированы».
- Настоящий каталог HLTV вернул 100 результатов; матч BETBOOM—FURIA 2399755, архив demo/113289 размером 525648852 байта скачан, проверен и разобран: Dust2 29 раундов, Cache 21 раунд, по 10 игроков.
- 42 Python-теста; 56 Flutter-проверок и отдельная живая проверка очереди. Новые эталоны UI studio-*-08.png. Анализ без замечаний.
- Windows-инсталлятор 0.8 установлен успешно; Android APK 0.8 собран и подпись v2 проверена. Пакеты исходников/сервера и контрольные суммы подготовлены. Windows-инсталлятор повторно собран 2026-11-01 в CI, скачан и проверен; Android APK остался на Windows и не входит в текущие вложения релиза.

## Где код

client/lib/data/account_roster.dart — привязка серверной команды к локальному кэшу.
client/lib/data/tactical_sync.dart — версии, pull/push, долговечная очередь, конфликты, радары.
client/lib/data/store.dart — SQLite v3.
client/lib/ui/workspace.dart — рабочая область, таймер/индикатор синхронизации.
client/lib/ui/account_page.dart и online_team_page.dart — аккаунты, состав, приглашения.
client/lib/ui/editor.dart — редактор T/CT, заметки, этажи и блокировка несохранённых правок.
worker/hltv_catalog.py — каталог/карточки/скачивание.
worker/demo_worker.py — DEM/ZIP/RAR и анализ.
native/download/main.cpp — Windows WebView2-загрузчик.
server/ — backend и миграции; tools/ — сборки/упаковка/проверки.
CHECKS.md и CHECKS_0.*.md — проверенные результаты и ограничения.

## Сервер и доступы

Публичный API: https://teamsync-api-ui7n.onrender.com
Платформа: Render Free, PostgreSQL: Neon Free. Серверный код в приватном GitHub BrainMcLore/teamsync-api. Последний известный опубликованный commit: ba14e807d8c03dd6ce09b1f826210b7c1d3f61e7. Backend версии 0.7 совместим с клиентом 0.8; менять сервер ради номера клиента не нужно.
Полный исходный проект теперь также размещён в отдельном приватном GitHub BrainMcLore/teamsync; Git remote github. Windows release workflow успешно проверен: https://github.com/BrainMcLore/teamsync/actions/runs/41259787893 .
Секреты Neon и Discord находятся только в Render env. В архив не включать пароли, токены, OAuth Client Secret, браузерные профили, ключи подписи. На Linux войти в GitHub/Render/Neon самостоятельно при необходимости. Удалённые сервисы не переносить и не создавать дубликаты.

## План на Arch

1. Скопировать и распаковать исходники в пользовательскую папку. Windows .tools, .venv, build и SDK не переносить как Linux-инструменты. Переустановить подходящие Linux SDK отдельно, сохранив pubspec.lock и Python requirements.
2. Установить актуальное официальное приложение ChatGPT для Arch, войти в тот же аккаунт, открыть папку TeamSync в Codex. Официальная инструкция: https://learn.chatgpt.com/docs/linux/linux-app . Не устанавливать сторонние перепакованные сборки вместо официальной без явного выбора пользователя.
3. Для продолжения в новом чате дать агенту прочитать этот файл, CHECKS.md, README.md и текущие исходники. Это сохраняет рабочий контекст, но не импортирует полную историю.
4. Этот чат уже продолжен на Arch. Рабочая папка: /home/admin/projects; резервная исходная копия: /home/admin/teamsync. Общий локальный origin: ssh://admin@192.168.1.106/home/admin/repos/teamsync.git. Чат не публиковать и не добавлять в Git.
5. Продолжать выпуск Windows/Android. На Linux проверять скрипты/сервер/упаковку; Windows-инсталлятор собирать на Windows или Windows runner GitHub Actions. Папку client/linux и Linux-загрузчик не создавать. Настоящие EXE/APK от предыдущей успешной сборки остаются на Windows; перенос исходников не переносит SDK, ключи подписи или пользовательские данные.

## Личные материалы и сессии

Исходники не содержат личную базу и демки. Старые локальные данные на Windows: %APPDATA%/app.teamsync/teamsync. Не копировать работающую SQLite с WAL обычным пофайловым способом — использовать SQLite backup/экспорт или закрыть приложение.
Сохранить при необходимости DEM/разборы, пользовательские радары, снимки плейбука и локальную базу отдельным приватным архивом. Абсолютные Windows-пути при Linux-импорте требуют переназначения. flutter_secure_storage.dat защищён Windows DPAPI и не является переносимой Linux-сессией: на новом устройстве нужен повторный вход. Текущий архив — исходники и контекст; пользовательские файлы и полный чат пока не перенесены.
